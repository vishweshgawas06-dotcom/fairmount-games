# P03-T02i — Private pseudonymous authentication attempt guard

**Status:** [PostgreSQL CI 39921986980](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/39921986980) passed (2026-10-23). No public login/MFA route is enabled.

Add revision `20261023_03` and `identity/auth_attempts.py`: transaction-serialized HMAC-keyed subject and transport-source windows, plus append-only failed/throttled audit rows. Only keyed SHA-256 digests, surface/outcome and DB timestamp are stored—not usernames, IPs, passwords, MFA codes or tokens. The caller supplies a distinct 32+ byte restricted deployment secret outside DB/repository (not the owner MFA encryption key), a **transport-verified** IP (never a raw forwarded header), and the trusted authentication callback/expected denial classes. Identifiers that are empty/overlong share an invalid-subject bucket. The private wrapper locks both buckets in deterministic order, uses DB clock and a SAVEPOINT for failed authentication, then records the generic failure in the caller's outer transaction. Unknown account labels consume the same budget as known ones. Unexpected infrastructure errors propagate and roll back, rather than being disguised as bad credentials.

Initial conservative **engineering defaults pending deployment review:** per identifier/surface, 5 failures per 15-minute window; per IP across surfaces, 30 failures per 15 minutes. A valid proof clears only the subject bucket, not source failures. A blocked request never invokes the credential callback. The caller must commit even a denied attempt; on success it must commit before returning the secret token. No in-memory per-worker bypass and no raw secret in `repr`.

PostgreSQL tests exercise nonexistent subjects, source/subject independence, throttling, window restart, pseudonymous persistence, invalid context, and database-level immutability of failure events. **Open before any public route:** D-02 retention/deletion/backups for audit/counters, secure secret custody/rotation, verified reverse-proxy IP contract, request-edge denial handling and retry response, rate-limit/load review, multi-connection race and callback integration with owner/member/MFA issuers. This is not evidence that authentication is currently throttled at HTTP—the only route remains liveness.
