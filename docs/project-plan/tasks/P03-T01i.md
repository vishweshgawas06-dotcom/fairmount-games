## Implementation

- Alembic revision `20261016_07` creates `security_events` with server timestamp, opaque ID, controlled event/source vocabulary, target-account FK, optional actor-account FK and target/time index. No column can store free-form secrets/PII. Null actor is limited to trusted local owner bootstrap/reissue events.
- PostgreSQL triggers reject UPDATE, DELETE and TRUNCATE. A later D-02-approved retention/anonymization policy would require a deliberate migration; no historical row is silently discarded.
- Integration tests assert actor/source/target restrictions, exact minimal column set, immutable rows and retained original event after failed writes. No service writes audit events yet, so this is **not** proof of audited workflows.
