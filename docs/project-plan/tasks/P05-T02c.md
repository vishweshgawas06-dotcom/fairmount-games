# P05-T02c — Private owner-funded reserve deposits

**Status:** Internal implementation complete (2026-10-23); [PostgreSQL CI 39911706081](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/39911706081) passed. No reserve withdrawal, bet admission, roulette payout or public funding route.

`fairmount_api.reserve_funding.fund_game_reserve` requires a currently enabled owner session with MFA verified within ten minutes. In one caller-owned transaction it locks the sole owner Account/session, idempotency scope, singleton reserve **before** the owner wallet, verifies the full amount is available, then records one `RESERVE_FUND` operation and two immutable opposite ledger effects. No direct reserve issuance, agent/player reserve funding, partial transfer, hidden replenishment or RNG use is permitted. A replay with the same key and full canonical intent returns the original operation ID without moving points again; changed intent conflicts. Commit must succeed before the user is told it succeeded.

The owner can now deposit existing owner-wallet points **internally**, but cannot withdraw until all unsettled round payout-or-void obligations are persisted, locked and checked against the remaining reserve in the same transaction. There are still **no** bets, round/obligation persistence, reserve-protected withdrawal, HTTP/MFA step-up route, request-edge throttling/failure audit, cookie/CSRF controls or independent-concurrency tests; this does not enable wagering or authorize accepting an underfunded bet.
