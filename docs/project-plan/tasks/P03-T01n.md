# P03-T01n — Internal audited owner-bootstrap transaction

**Status:** Implemented; PostgreSQL CI pending (2026-10-19).

**Authorization:** D-12 approves the owner personally running a local bootstrap command, a 24-hour one-time initial secret, and local pre-activation reissue. D-14 fixes the public `owner` login label. This slice adds *internal transaction functions only*; no CLI, remote route, activation, owner MFA enrollment, login or session is created.

## Implementation

- `bootstrap_owner(connection)` inserts the single OWNER account, pending digest-only credential and `OWNER_BOOTSTRAP_ISSUED` event in the caller's transaction. The unique OWNER index remains the final concurrency guard. It returns an ephemeral secret in a redacted-repr result; it neither commits nor prints it. The future local CLI must commit first, then display once on the owner's protected terminal. On failure, never deliver the secret.
- `reissue_pending_owner_secret(connection)` locks OWNER then credential row, rejects missing/disabled/activated owner or any existing MFA factor, atomically replaces the old pending digest and 24-hour timestamps, and appends `OWNER_BOOTSTRAP_REISSUED`. The old secret cannot be used after a committed replacement. This is **only pre-activation**, not an owner MFA reset or recovery bypass.
- PostgreSQL tests cover issue/rotate, digest replacement and audit, duplicate refusal, savepoint rollback with no partial owner/credential/audit, disabled/activated owner refusal and existing MFA refusal. No plaintext secret is stored in an account or event row.
