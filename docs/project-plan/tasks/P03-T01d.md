# P03-T01d — Fixed V1 player usernames

**Status:** Complete for the fixed V1 player-username slice, 2026-10-16.

**Authorization:** The owner granted step-by-step implementation permission on 2026-10-16. The P03-T01a contract already approves fixed V1 player usernames; this slice only enforces that invariant. No new registration, credential, session, wallet or deletion/reuse workflow is introduced.

## Implementation

- Alembic revision `20261016_04` adds a PostgreSQL trigger: once a `PLAYER` identity has a non-null canonical username, updates cannot change its login kind, username or account ID; deleting that assigned identity is rejected. Initial null → valid username assignment remains possible. Display/mobile changes and disabled status changes are unaffected. D-01 prescribes disabling, not hard-deleting, players.
- Other identity rows are not governed by the player-username trigger. This is not a decision to permit Agent-ID changes in the final product: future provisioning and identity-lifecycle design must review agent ID immutability. No username release, tombstone, anonymization or retention policy is invented; D-02/D-11 remain open.
- Alembic autogenerate does not compare triggers. Dedicated PostgreSQL tests verify that the migration's trigger exists through behavior (including delete and update attempts) alongside CI's migration round-trip and metadata check.
