# P04-T02e — Committed agent assignment HTTP-scope acceptance

**Status:** Local checks and [CI 40188664573](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/40188664573) passed (Python 3.12/PostgreSQL, migrations, Node and Ruff).

A disposable PostgreSQL integration test seeds two AGENT accounts, three PLAYER accounts, two current assignments and two valid agent sessions, then commits. Subsequent direct-HTTPS requests with each agent's cookie use fresh database transactions and the **real** scoped player-wallet route and data-layer locks. The first agent can read the assigned player but not the other agent's player, an unassigned player or an agent wallet. The second agent cannot read the first player's wallet until the assignment is ended and reissued to them in a committed transaction. After reassignment the old agent is denied; after disablement the new agent is denied that player while retaining access to the other assigned, enabled player. All denial bodies are generic.

The test uses deliberately seeded sessions/assignments rather than agent login, account creation or a reassignment API; it does not establish who may perform an owner-managed reassignment through a request. The fixture must use the disposable CI test database because wallet rows are immutable and are not deleted. It does not approve reverse-proxy trust, dashboard roster exposure, gambling/transfer writes or a production deployment.
