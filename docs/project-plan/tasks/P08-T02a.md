# P08-T02a — UUID round/accepted-bet schema and independent result persistence

**Status:** Structural/internal implementation complete (2026-10-23); [PostgreSQL CI 39914613660](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/39914613660) passed. No live bet-admission endpoint, settlement, recovery worker, result feed or UI.

Incremental Alembic revision `20261023_02` preserves all existing identity/accounting history. It adds global UUID round rows with exact **50-second server cutoff** and **60-second reveal** timestamps, at most one `OPEN` round, a persisted 0–36 result and state constraints; round transition triggers reject outcome rewrites, reopening terminal rounds and history deletion. Accepted-bet rows have UUID player/round/ledger references, role binding, 5-point stake units and immutable history. A PostgreSQL bet-insert trigger locks the round and replaces any supplied timestamp with `clock_timestamp()`, rejecting non-open or post-cutoff bets. Deferred DB checks require each `BET_STAKE` operation to match **exactly one** accepted bet, player, amount and context ID, with paired wallet→reserve ledger effects from P05-T01b. The existing legal-position catalogue and POOL-01 policy still require a validated transactional admission service; the DB schema alone cannot reject an underfunded prospective bet or validate the selection key against Python's catalogue.

Private `roulette.round_clock.open_round` reads the database clock rather than accepting client time; `close_round` locks a round, checks the cutoff *after locking*, generates a cryptographically secure `secrets.randbelow(37)` result **without bet/stake/wallet/player inputs**, persists it once, and returns the stored result on idempotent replay. A private `_test_rng` hook is only for deterministic tests and must never be bound to an HTTP request, worker config or user action. Result publication must wait until `reveal_at`, and payout requires a later atomic settlement transaction; this slice does neither. D-06 worker failover/irrecoverable-failure recovery remains open; no arbitrary retry timeout or reroll is added.

**Not a release gate:** The database account used by CI can write directly to tables; do not grant an application role unrestricted ledger/bet/round writes or mistake structural checks for the owner-approved atomic POOL-01 reserve-admission, cap and authorization service. No accepted bet may be exposed without those checks, disabled-player handling, idempotent settlement/refund and real concurrency evidence. A future `VOID_REFUNDED` transition must be paired with full refunds, never raw state mutation.
