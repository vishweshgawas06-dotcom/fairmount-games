# P04-T01a — Private resource-scoped wallet and accepted-bet reads

**Status:** Local non-DB checks passed (2026-10-23); PostgreSQL CI pending. This is an implementation of the explicit owner/agent/player visibility constraints, not owner approval of the complete P04 policy matrix. No HTTP/WebSocket route is enabled.

`resource_reads.py` resolves the live session in the caller's transaction, pins target Account state under a row lock and—for agents—pins the live assignment row. It returns only a wallet balance or an immutable accepted-bet projection for an expressly requested target. Invalid, unknown, disabled or unassigned targets receive the same generic denial. The calling transaction must commit before sending any data and never expose raw ORM rows. A future list endpoint must recheck assignment/disablement on *each* row, not merely filter an initial snapshot.

| Resource | Owner | Agent | Player |
| --- | --- | --- | --- |
| Wallet | Any account for reconciliation, including disabled-account obligations | Own wallet; **enabled, currently assigned** player's wallet | Own enabled wallet only |
| Accepted-bet history | Any player, including disabled account for audit | **Enabled, currently assigned** player's history | Own enabled history only |

Agent and player sessions must be enabled/unexpired; disabling an account revokes the session. A player disabled after acceptance still receives a private settlement/refund credit, but cannot use a normal session to view or transfer until authorized restoration. Bet history contains no other player's rows and no credential/private identity fields. Owner has broad audited visibility but this does not grant an agent access to owner-managed or another agent's players. A prior assignment never authorizes current reads after reassignment.

PostgreSQL integration tests check cross-agent/cross-player ID tampering, unassigned/disabled/reassigned targets, owner visibility of disabled obligations, and projection of a real accepted bet. Realtime subscriptions, list-query races, public response serialization/cookies/CSRF, failure audit and broader P04 owner-reviewed role/action matrix remain separate gates.
