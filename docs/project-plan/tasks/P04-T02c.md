# P04-T02c — Committed HTTP session-to-private-read integration

**Status:** Implemented; local Ruff and non-DB suite passed. PostgreSQL CI pending.

One disposable PostgreSQL CI database test now creates a unique activated PLAYER, commits the fixture and uses a direct-HTTPS ASGI test client to log in through the real guarded password issuer. Subsequent self-wallet and empty recent-bet requests use the browser's real secure cookies and independent SQLAlchemy transactions, confirming a committed session is visible outside its issuing connection. It checks exact minimal responses, a refused client-selected history query, the stored token *digest* rather than the raw token, a failed logout without CSRF, successful same-origin CSRF logout, persisted revocation, stale-cookie rejection on both routes, and disablement revoking a freshly issued session. No issuer/read/revocation or schema checks are mocked; only deployment-owned DB engine and auth HMAC key loading are injected. This test deliberately runs last in a disposable test database because success audit and wallet rows are immutable; it must never be run against a real deployment database.

It does **not** prove owner MFA, bets on this integration fixture, authorization for another player's history at the HTTP edge, real TLS termination or an approved reverse-proxy trust model. The proxy preview stays read-only and cannot run direct-TLS login. Continue P04 per-resource/assignment API gates, then gameplay-write CSRF and separately supervised deployment acceptance.
