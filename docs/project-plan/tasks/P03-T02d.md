# P03-T02d — Internal two-factor owner session issuance

**Status:** Complete (2026-10-19); [CI 39205689122](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/39205689122) passed.

An internal `issue_owner_session` transaction requires the exact public label `owner`, enabled account, verified Argon2id password, and successful locked TOTP/recovery proof before issuing a 256-bit random bearer token. It revokes the former unrevoked owner session only **after** both factors succeed, inserts a digest-only owner session with D-03 15-minute idle/8-hour absolute deadlines and current MFA timestamp, and atomically appends a token-free `OWNER_SESSION_STARTED` audit event. A caller must commit before handing over the raw token. Rollback undoes code consumption, session revocation/issuance and both success events; the raw token is never stored or included in result `repr`. Migration `20261019_03` extends the append-only event whitelist. Existing sessions are replaced regardless of expiry, since the partial unique index still reserves expired unrevoked rows.

**Not public-ready:** No HTTP login, rate limiter, durable failure accounting, safe cookies/CSRF, endpoint or realtime authorization, protected production MFA-key deployment, logout/disablement proactive revocation, or no-factors-left recovery exists. A session row alone does not authorize a request. In particular, this function must not be exposed until throttling and failure auditing resist password and recovery-code guessing. Downgrade of the event constraint after issuance needs audit retention review; do not delete events to force it. See [session boundary](../auth/SESSION_SCHEMA_BOUNDARY.md).
