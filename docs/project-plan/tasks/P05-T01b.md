# P05-T01b — UUID wallet/reserve/paired-ledger schema

**Status:** Structural implementation and local non-DB tests complete (2026-10-23); PostgreSQL CI still required. No issuance/transfer/funding/bet service or public route exists.

This checkpoint builds on the [UUID funded-ledger design](../database/UUID_FUNDED_LEDGER_DESIGN.md) **without** replacing identity history with PR #2's BIGINT account schema. Incremental Alembic revision `20261023_01` adds UUID-keyed account wallets, a separate singleton reserve, UUID operation IDs, a signed append-only entry journal, actor-role FK, account-scoped idempotency keys and request fingerprints. All preexisting account rows get zero wallets on upgrade; account inserts get zero wallets in the same transaction. The separate reserve starts empty. Issuance is owner-to-owner-wallet only; operation type/endpoint constraints distinguish authorized-shape transfers, reserve movements and game entries (which require an opaque context reference). No operation can create arbitrary account credits under the issuance type.

Journal inserts materialize balances transactionally; nonnegative checks reject overdrafts, and database triggers block direct balance updates, point-history update/delete/truncate and removal of reserve/wallet rows. A **deferred constraint trigger** prevents commits with an incomplete or mismatched effect set: issuance must have one exact owner-wallet credit; a transfer must have the matching debit/credit and no extras. The migration downgrade refuses to destroy a populated operation journal; empty-test migrations may round-trip. These structural checks are defense in depth, **not** operator authorization, full replay-intent comparison, a proven funded-reserve withdrawal lock, bet/round persistence, a runtime reconciliation service or a production DB role/privilege policy. Superusers/DDL can bypass triggers; deployment roles must not have table-owner or TRUNCATE privileges.
