# P08-T02b — Private late-result recovery step

**Status:** Local checks pending CI (2026-10-24). No autonomous worker, public reveal or payout route.

After the owner's [D-06a](../decisions/2026-10-24-round-result-recovery.md) choice, `roulette/recovery.py` adds caller-transaction-owned, retryable due transitions. `advance_one_due_round` reads the database clock and processes one due OPEN round into a persisted, independently selected result at/after cutoff, **or** one due CLOSED round with a persisted result into atomic settlement at/after reveal. A late result is selected even after the nominal reveal time; no timeout-void branch exists. The caller must **commit each transition separately** before calling again, avoiding round→reserve lock-order inversion. Concurrent workers may race on the same round; `close_round` reuses the single persisted result, `settle_round` replays a terminal payout. `open_next_due_round` uses a transaction advisory lock and the one-OPEN DB index to open a fresh DB-clock round only after the previous reveal time, never backfilling rounds missed during an outage.

P11 settlement now rejects a void on any persisted result, even if a trusted incident caller races against payout. Tests verify that a delayed due step persists 17 independently (deterministic test RNG only), subsequently pays 350 total, never refunds a known result, and opens one fresh round rather than duplicating an existing OPEN round. The existing isolated-schema terminal race now requires settlement to win regardless of request order. The exceptional void primitive still exists only for an OPEN/no-result round; its authorization requires a separate decision.

This is an internal *step*, not a supervised polling process or production deployment. Worker crash between committed close and settlement, two concurrent pollers opening a round, monitoring/backoff and request-facing delayed-result status are subsequent gates. No routine automatic void or reroll is authorized.
