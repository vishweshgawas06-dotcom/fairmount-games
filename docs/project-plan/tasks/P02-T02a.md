# P02-T02a — First PostgreSQL physical schema slice

**Status:** Implementation prepared; PostgreSQL CI verification pending.

**Authorization:** Owner approved P02-T02a on 2026-10-16. Scope: accounts, separated private identity, agent assignment history, one reviewed Alembic migration and PostgreSQL constraint tests. No authentication/login/reset APIs, wallets, point ledger, rounds, bets, settlement, realtime, or deletion jobs.

## Schema choices and deferred decisions

- `accounts`: generated opaque UUID, `OWNER`/`AGENT`/`PLAYER` role, enabled/disabled status, timestamps, unique partial index permitting **at most one** owner. Bootstrap/recovery of the one owner is not implemented.
- `private_identities`: one-to-one restricted FK to account, optional display name, mobile and login identifier. These are deliberately nullable and **not unique yet**: D-02/PRIV-01 has not approved how usernames/mobiles are reused after anonymization. No password/hash/token is stored by this slice; P03 must define secure credentials and registration requirements.
- `agent_assignments`: historical player→agent rows with actor and timestamps, no overlap of two *currently open* rows for one player (partial unique index); owner-managed players may have none. FKs block missing account references and self-assignment is disallowed. DB FKs alone do **not** prove player/agent/actor roles, account enabled status, authorized reassignment, or non-overlapping historical intervals. Those require future service/database review before user-management APIs.
- Migration uses PostgreSQL 16 `gen_random_uuid()`, reversible in an **empty isolated test database**. A downgrade drops the three tables and their data: do not downgrade a database whose data you need. No production migration policy is claimed.
- Alembic's local-only runner permits only loopback `fairmount_dev` or `fairmount_test`, with credentials from ignored `.env` or environment. No production deployment configuration is supplied.

## Local review and limitations

Docker is unavailable in the agent sandbox; do not claim local PostgreSQL execution. The tests explicitly skip PostgreSQL cases unless `FAIRMOUNT_RUN_DB_TESTS=1`; CI sets that flag and must fail if the migrated test DB is missing. Existing API liveness and fixture tests are independent. D-02/PRIV-01, D-03, role-aware authorization, assignment race/deadlock tests and full deletion/retention design remain future gates.
