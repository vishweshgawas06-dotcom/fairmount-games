# P03-T01f — Credential cryptographic primitives

**Status:** Complete for pure cryptographic primitives, 2026-10-16.

**Authorization:** Owner approved step-by-step development, Argon2id password direction in D-10/P03-T01a, generated one-time activation credentials and D-12 owner bootstrap direction. This slice adds **only pure cryptographic helpers** and tests, not account issuance, credential persistence, sessions, MFA, registration or login.

## Implementation

- Add `argon2-cffi` runtime dependency and `hash_password` / `verify_password` helpers with explicit Argon2id parameters (time 3, memory 64 MiB, parallelism 4, salt 16 bytes, hash 32 bytes). Fresh salt per hash; reject non-Argon2id or malformed stored hashes. Final parameters need benchmarking and security review on deployment hardware.
- Generate 32 random bytes as a URL-safe initial secret, store only its SHA-256 digest, and use constant-time digest comparison for verification. SHA-256 is appropriate for this **256-bit generated random secret**, not as a password hashing substitute. Never store readable secrets. The `verify_initial_secret` helper deliberately does **not** check expiry, single-use consumption, account state, rate limits or audit; those must be enforced atomically by a later database-backed service.
- Unit tests cover fresh salts, right/wrong/malformed passwords, generated-secret uniqueness/format, digest checks and invalid input. No endpoint uses these helpers yet; no owner can authenticate through this code.
