# P15-T02b — Read-only due-round inventory for operators

**Status:** Local non-DB gate passed; Python 3.12/PostgreSQL CI pending. No deployment, alert threshold or auto-void.

`roulette/worker_diagnostics.py` observes the PostgreSQL clock under a stable read-only snapshot. It counts OPEN rounds past cutoff (still owed independent result persistence) and CLOSED rounds past reveal (still owed settlement of the saved result), records the oldest due timestamp and latest round state, and does not select any wagers, balances, users, RNG state or ledger details. `python -m fairmount_api.roulette.worker_status_cli` uses the separately provisioned `FAIRMOUNT_WORKER_DATABASE_URL`, checks the exact migration revision, and outputs one machine-readable JSON line. Missing/unsafe URLs, stale schema or SQL errors yield only a generic error and exit code 2; never print connection errors or credentials. Due counts are returned with exit code 0 because a nonzero count is not automatically an incident: supervisor alert thresholds and D-04 latency targets remain undecided.

PostgreSQL tests must verify OPEN overdue → independently persisted CLOSED overdue → SETTLED inventory against the actual round clock without mutating balances from this reader. Pure tests verify URL/DB/migration failures never echo credentials and successful output never contains private game data. This is **not** a heartbeat, leader election, reconciler, automatic correction or recovery worker. An operator must still supervise/restart the separate poller, monitor lag against approved thresholds and escalate failed obligations; never void or patch a wallet based on this snapshot.
