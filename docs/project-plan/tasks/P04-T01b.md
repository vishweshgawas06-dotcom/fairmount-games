# P04-T01b — Live dashboard player roster

**Status:** Local non-DB gate passed (2026-10-23); PostgreSQL CI pending. No dashboard HTTP/WebSocket route.

`list_visible_player_ids` enforces the locked enabled-status/current-assignment visibility rule inside a caller transaction: owner sees enabled players (including owner-managed/unassigned), agent sees only enabled players **currently** assigned to that agent, and a live player sees only themself. The agent's initial assignment candidate list is not treated as authorization: it locks/rechecks each target Account and live assignment before returning a projected UUID list. Stale sessions, disabled players and ended assignments cannot remain visible. Every later resource read must independently reauthorize the target, and the caller must commit before transmitting a response.

PostgreSQL tests exercise owner-managed/unassigned players, two different agents, reassignment, disablement and revoked player session. This is an internal read primitive, not an owner-approved full role/action matrix or production list endpoint. Large-roster pagination, realtime invalidation, request-edge auth/CSRF and multi-connection reassignment races remain open.
