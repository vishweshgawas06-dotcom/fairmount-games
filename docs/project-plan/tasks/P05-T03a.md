# P05-T03a — Read-only point journal reconciliation

**Status:** Internal implementation and local non-DB gates complete (2026-10-23); PostgreSQL CI pending. No scheduled worker, reconciliation route or silent balance repair.

`fairmount_api.point_reconciliation.reconcile_points` requires a transaction at PostgreSQL `REPEATABLE READ` or `SERIALIZABLE` isolation so its multiple SELECTs observe one coherent snapshot. It compares every UUID account-wallet balance with its immutable signed ledger sum, the singleton reserve balance with its reserve ledger sum, and **all materialized wallet/reserve points** with the sum of explicit owner issuance operations. Its immutable report names mismatches and a global supply discrepancy. It never mutates balances, issues points or conceals a shortfall; an operational caller must alert/block affected money-moving activity and investigate rather than overwrite history. A privileged/DDL actor can bypass application triggers, so production runtime DB privileges and backup/recovery procedures remain separate gates.
