# P03-T02f — Internal session logout and append-only audit

**Status:** Complete (2026-10-19); [CI 39207809470](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/39207809470) passed.

`revoke_presented_session` accepts only a correctly shaped bearer token, finds its SHA-256 digest, locks Account → AccountSession in the same order as validation/login, and revokes an unrevoked session even if its idle/absolute deadline has elapsed. After P03-T02g, disablement already revokes the row, making subsequent logout a no-op. A repeat, malformed, unknown or already-revoked token is a no-op. The caller must commit before acknowledging logout. A successful revocation appends one token-free `SESSION_REVOKED` security event with the account as actor and target; actor attribution means **bearer possession**, not fresh MFA. Alembic revision `20261019_04` expands the event whitelist. No raw token is stored or logged. Future-issued corrupt session timestamps are handled without violating the DB check by setting revoked time to at least issued time; the event uses actual DB time.

**Boundaries (updated 2026-10-24):** [P03-T02o](P03-T02o.md) now provides an opt-in **direct-TLS-only** same-origin CSRF/cookie-clearing HTTP adapter; it is disabled in the preview and lacks a full browser login→protected-resource→logout integration test. P03-T02g added proactive DB-backed revocation on disablement/password changes, but public account-change routes and realtime disconnect are still absent. A session row must be checked again on every protected HTTP/realtime operation; merely marking it revoked is not enough to close an already-authorized socket. D-02 log retention remains unresolved; no cleanup is introduced. Downgrading an event constraint after immutable logout events requires an explicit retention review.
