# P03-T02m — Future request-edge cookie and CSRF contract

**Status:** Local tests and [CI 40084292244](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/40084292244) passed (Python 3.12/PostgreSQL). The cookie setter is now used by the opt-in [P03-T02n](P03-T02n.md) login after commit; the unsafe-request CSRF guard now protects opt-in [P03-T02o](P03-T02o.md) logout, but is **not** wired to gameplay/point write routes.

`identity/http_boundary.py` defines a narrow reusable future request boundary: server-issued `__Host-` session cookie (Secure, HttpOnly, host-only, SameSite Strict, Path /), a separate Secure/JS-readable `__Host-` CSRF cookie, role-bounded cookie lifetimes, and explicit clearing. Its mutating-request guard requires a configured canonical HTTPS origin, matching Host/Origin, exactly one valid session cookie, exactly one CSRF cookie and a matching single CSRF header with constant-time comparison. Duplicate/malformed cookies, absent/cross-site origins and header ambiguity are denied generically. The returned token remains **untrusted** until the caller's transaction validates its live session, role, assignment and resource. A future handler may set cookies only *after committing* guarded session issuance; neither cookie is an authorization grant by itself.

Tests cover cookie flags, role limits, clearing, successful same-origin requests, mismatches, duplicates and malformed requests. The opt-in login uses the cookie setter, and opt-in logout now uses the session/CSRF guard; gameplay and point-write handlers remain unavailable. Trusted peer-IP extraction/rate-limit adapter integration, reverse-proxy and TLS contract, secure browser login/logout, stale-session/request-edge authorization and CSRF on actual routes remain open. Never expose unguarded private issuers directly to HTTP.
