# P08-T02c — Opt-in stateless round poller and committed recovery test

**Status:** Local gates pending CI (2026-10-24). No deployment or public gameplay route is enabled.

`roulette/worker.py` adds an **opt-in** process entry point (`python -m fairmount_api.roulette.worker`) requiring a separately supplied PostgreSQL URL. It is not started by the API or a scheduler. `run_once` commits exactly one due transition per call, or opens one next round; close and settlement use **different** committed transactions in the reserve-compatible lock order. `poll` retries database/unavailable-step failures with bounded backoff, reports only exception type (no URL, SQL params, tokens or early result), and does not auto-void or invent a different pocket. Unexpected programming errors escape for external supervision. Its transaction advisory lock and partial unique index prevent multiple pollers opening duplicate rounds; existing round/result and reserve locks make retry after a crash idempotent. An outage skips missed cycles rather than backfilling fictional games.

The isolated migrated PostgreSQL fixture simulates a late round after the 50-second cutoff, commits `run_once` with the server RNG, then behaves like a new worker invocation: it reuses the exact saved number, settles exactly once after reveal, reconciles the wallet/reserve ledger and opens at most one new round. Results are checked for 0–36, not chosen from bets/stakes or client data. Test-only privileged timestamp warp restores the round immutability trigger before any worker call.

**Operational blockers:** no process supervisor/restart deployment, secure URL provisioning/rotation, alerts/on-call runbook, production PostgreSQL latency/drift/load evidence, UI for delayed result or request-edge authentication. Failure to settle must keep the obligation unresolved and page operators; `poll` logging alone is not a production alert. [D-06a](../decisions/2026-10-24-round-result-recovery.md) is approved for a missing result, but exceptional-void authorization is not.
