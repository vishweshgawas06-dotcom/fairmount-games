# P03-T02h — Internal agent/player session issuance

**Status:** Implemented; PostgreSQL CI pending (2026-10-19).

D-03 approves one active session for **each** role with agent 30-minute idle/12-hour absolute and player 30-minute idle/24-hour absolute deadlines. `issue_member_session` accepts only the `AGENT` or `PLAYER` role and its matching canonical fixed Agent ID or player username; a username cannot be submitted in the agent namespace or vice versa. It checks the current enabled account, fixed identity and active Argon2id password credential under locks, then replaces only that account's older session after successful password proof. It generates a 256-bit random bearer token, persists only its SHA-256 digest, records role-specific deadlines and atomically appends a token-free `MEMBER_SESSION_STARTED` success event. Rollback restores any previous session and removes both new session and audit. Alembic `20261019_06` expands the event whitelist without inventing identity reuse or retention policy.

**Boundaries:** No agent/player provisioning, activation, reset, registration, login route, rate limit or failure audit exists yet; these tests seed *already-activated* accounts only. Do not expose this internal issuer over HTTP until rate limits, CSRF/cookies, actor/resource authorization, account creation/activation and realtime invalidation are verified. Login is not management authorization: assignments and enabled status must be checked per resource. There is no owner bypass, MFA downgrade, wallet or betting behavior here.
