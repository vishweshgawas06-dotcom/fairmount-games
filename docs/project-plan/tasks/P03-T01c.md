# P03-T01c — Bind login kind to account role

**Status:** Complete for bounded role-binding DB slice, 2026-10-16.

**Authorization:** On 2026-10-16 the owner broadened permission to complete the phases in small tested/debugged steps and ask about unresolved decisions. This bounded first step follows the [role-binding design](../auth/NEXT_PROVISIONING_SLICE_DESIGN.md). It adds **no** registration, credential, session, wallet or gambling code.

## Implementation

- A new PostgreSQL/Alembic migration adds a unique `(accounts.id, accounts.role)` referenced key and a composite FK from `(private_identities.account_id, private_identities.login_kind)` to `(accounts.id, accounts.role)`. The original `account_id` FK remains: rows with both login fields null still need an account. The existing P03-T01b CHECK makes a non-null kind accompany a valid login identifier.
- The FK prevents a player login kind on an agent/owner account, an Agent ID on a player/owner account, and role changes that would mismatch a bound login. It does **not** prohibit changing one valid username into another or changing the role of an account with null login kind.
- Existing mismatched rows abort the migration instead of silently being rewritten. CI runs a deliberate legacy mismatch at revision 02 and checks that failure preserves both the old revision and row. No production backfill is performed.
