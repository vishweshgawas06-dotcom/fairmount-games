# P11-T01b — Competing players, one global funded liability

**Status:** Real-PostgreSQL race test/local non-DB gate written (2026-10-23); PostgreSQL CI pending. No public betting route or payout/void service.

The isolated-migrated-schema concurrency fixture in `tests/test_point_concurrency.py` now additionally funds 340 points into the owner-funded reserve, gives two distinct players enough wallet balance for a requested 10-point stake, opens a database-clock round, and starts **two independent connections together** on `straight:17`. After one candidate stake, the reserve has 350 points and covers that bet's 350-point total payout. Admitting both would create a 700-point worst outcome against 360 reserve points. The global reserve row lock and persisted-bet projection must therefore admit **exactly one** and reject the other without a partial debit; the immutable journal and 1,100 total issued supply must still reconcile. Player wallets are checked so only the successful candidate loses 10 points. This catches lost-update/optimistic-read failures not visible in isolated single-transaction tests.

This test is not proof for every possible interleaving, multiple simultaneously unsettled rounds, cap-racing players, settlement/reserve withdrawal overlap, worker failure or D-06 recovery. Those remain separate gates. Privileged direct SQL and public route authorization/rate limits/CSRF are also out of scope.
