# P02-T01 — Conceptual database schema and transaction design

**Status:** Design draft delivered for owner/technical review; not complete or approved for implementation.

**Phase:** P02 — Database and migrations

**Authorization:** Owner granted permission on 2026-10-15 for **conceptual schema and transaction design only**. No database code, SQL/ORM models, migration, gameplay engine, or deployment changes are authorized by this task.

## Scope and deliverable

Review [the conceptual schema and transaction design](../database/CONCEPTUAL_SCHEMA_AND_TRANSACTIONS.md), which sketches account/private identity/session and assignment records, wallets/ledger/agent budgets, rounds/outcomes/bets/exposure counters/idempotency/audits, locking order and transaction boundaries for betting, cutoff, settlement/void, rebet and disable/reassignment.

Use locked product rules and D-01. D-02 is partly open: design separation of personal data but do not set retention durations or create destructive cleanup. Treat proposed table shapes and lock order as hypotheses to validate against PostgreSQL later, not final schema choices.

## Acceptance/review checklist

- [x] Conceptual entities, relations and key/foreign-key/uniqueness/check candidates sketched.
- [x] Wallet/ledger and agent-budget accounting boundary identified, with unresolved source-of-points model visible.
- [x] One global round/outcome, server cutoff, per-number/exact-selection cap, duplicate bets and idempotency represented without changing approved rules.
- [x] Transaction sketches include rollback, deterministic locking, rebet atomicity, settlement versus refund exclusivity, and accepted bets surviving disable/disconnect.
- [x] Privacy, resource-level authorization, retention gaps and future PostgreSQL/concurrency verification called out.
- [ ] Owner/technical review of proposed schema/transactions and open decisions recorded; revise based on feedback.
- [ ] Obtain separate permission before any migration or implementation task.

## Evidence and limitations

This is documentation-only design work. `git diff --check` and relative Markdown links are checked; no database, concurrency or gameplay tests have been run because no implementation exists. P01-T01's earlier CI tests validate only the API liveness and catalogue fixture, not P02-T01. Do not mark P02-T01 complete until the conceptual review gate is recorded. Exact retention windows (D-02), round operational design (D-06), budget issuance/transfer model (ACCT-01), mobile reuse/anonymization (PRIV-01) and settlement scale/latency (OPS-01) remain open.
