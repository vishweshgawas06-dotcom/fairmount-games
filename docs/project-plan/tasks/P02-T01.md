# P02-T01 — Conceptual database schema and transaction design

**Status:** Complete as a conceptual design baseline — owner approved P02-T01 on 2026-10-16. No database implementation approved.

**Phase:** P02 — Database and migrations

**Authorization:** Owner granted permission on 2026-10-15 for **conceptual schema and transaction design only**. No database code, SQL/ORM models, migration, gameplay engine, or deployment changes are authorized by this task.

## Scope and deliverable

Review [the conceptual schema and transaction design](../database/CONCEPTUAL_SCHEMA_AND_TRANSACTIONS.md), which sketches account/private identity/session and assignment records, owner/agent/player wallets, owner-funded game reserve and ledger, rounds/outcomes/bets/exposure counters/idempotency/audits, locking order and transaction boundaries for betting, cutoff, settlement/void, rebet and disable/reassignment.

Use locked product rules and D-01. D-02 is partly open: design separation of personal data but do not set retention durations or create destructive cleanup. Treat proposed table shapes and lock order as hypotheses to validate against PostgreSQL later, not final schema choices.

## Acceptance/review checklist

- [x] Conceptual entities, relations and key/foreign-key/uniqueness/check candidates sketched.
- [x] Wallet/ledger boundary includes D-10 owner issuance, paired owner/agent/player transfers and proposed owner-funded game reserve; reserve coverage policy remains open.
- [x] One global round/outcome, server cutoff, per-number/exact-selection cap, duplicate bets and idempotency represented without changing approved rules.
- [x] Transaction sketches include rollback, deterministic locking, rebet atomicity, settlement versus refund exclusivity, and accepted bets surviving disable/disconnect.
- [x] Privacy, resource-level authorization, retention gaps and future PostgreSQL/concurrency verification called out.
- [x] Technical self-review recorded in [P02-T01 design review](../database/P02_T01_DESIGN_REVIEW.md); lock ordering and active-session wording corrected in the draft. This is not an independent review or PostgreSQL verification.
- [x] Owner approved P02-T01 as the conceptual design baseline on 2026-10-16. This accepts the reviewed structure for planning, **not** the unresolved POOL-01/D-06/D-02 rules or physical PostgreSQL design.

**Future authorization guard:** Obtain separate permission before any migration or implementation task. This is not a P02-T01 acceptance criterion.
