# P11-T01c — Private atomic settlement and full-void refund

**Status:** [PostgreSQL CI 39915748062](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/39915748062) passed (2026-10-23). No public settlement/void endpoint, worker or withdrawal.

`roulette/settlement.py` introduces two caller-transaction-owned primitives. `settle_round` accepts only a CLOSED round with a persisted, bet-independent server result at/after its database-clock reveal. It locks reserve → round → affected wallets, calculates the total approved return for **all** winning accepted bets from immutable DB rows, pays each player once via paired reserve-debit/wallet-credit journal operations, and marks the round SETTLED in the same transaction. Losing stakes remain in the reserve. Disabled players keep their accepted claims. No reroll, withheld win, or partial payout. An unexpected funding or wallet-overflow problem leaves the round unresolved for incident handling, not silently voided or settled. A repeated call to the same terminal state is read-only.

`refund_void_round` is a **private, trusted recovery primitive**, not a policy or route. It requires a nonempty incident reason, locks the same rows, refunds **every accepted stake** (including disabled players), and marks the round VOID_REFUNDED atomically; repeated calls do not pay twice. Opposite-terminal calls reject. **D-06 remains open:** no timeout auto-void, operator permission, worker failover, or missing-result recovery behavior is inferred. The existing schema requires OWNER attribution for automated payout/refund operations; the reason documents that these are system actions, not owner-login instructions. Future schema work should distinguish worker actor identity explicitly before exposing operations.

PostgreSQL-only tests use a privileged **test-only** round timestamp fixture, re-enable the guard before closing with the deterministic test RNG, and verify reveal gate, winner with disabled account, losing outcome, double-call replay, full multi-player void, terminal-state exclusion and journal reconciliation under a repeatable-read snapshot. This is not yet a live scheduler, multi-connection settlement race proof, or cross-round reserve withdrawal proof.
