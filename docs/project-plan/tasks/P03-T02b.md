# P03-T02b — Internal session validation and idle expiry

**Status:** Complete (2026-10-19); [CI 39204678377](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/39204678377) passed.

After the [P03-T02a schema](P03-T02a.md), this slice adds `resolve_session` for a future service to validate an existing, trusted, cryptographically issued 32-byte bearer token. It strictly checks 43-character URL-safe token shape, hashes the raw token, locks the matching account **then** session, reads PostgreSQL `clock_timestamp()` after locks, and rejects unknown, revoked, disabled, future-issued, idle-expired or absolute-expired rows. Disabled/expired rows are revoked atomically. A valid row has its idle deadline extended only up to its fixed absolute deadline. The result exposes account/session IDs, role and MFA timestamp to the caller, which must independently authorize every resource and sensitive owner action. No raw token is stored, logged or returned.

**Security boundary:** This internal method does not issue sessions, authenticate credentials or MFA, set cookies, provide CSRF protection, rate-limit endpoints, close WebSockets, revoke sessions proactively on account changes, or grant access to any route. Future callers must resolve and authorize inside a properly committed transaction; relying on a returned data object outside that boundary can create stale authorization. The database accepts seeded test rows, but a real issuer must prove password/MFA and create tokens securely. See [session boundary](../auth/SESSION_SCHEMA_BOUNDARY.md).
