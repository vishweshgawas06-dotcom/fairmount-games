# P04-T02h — Committed owner password + MFA HTTP resource lifecycle

**Status:** Local checks and [CI 40192542205](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/40192542205) passed (Python 3.12/PostgreSQL, migrations, Node, Ruff). Requires the disposable isolated CI database.

A committed integration test now performs the **actual private** owner bootstrap, password activation and encrypted TOTP enrollment with ten generated recovery codes inside a test database transaction, then tests the **actual HTTP direct-TLS** owner login with password and one recovery code. Only the deployment-owned engine, HMAC key and MFA key loader are injected; the guarded issuer, factor consumption, session issuance/cookie, resource authorization and logout/revocation use real database connections and transactions. The test verifies that one recovery code is consumed before resource access, OWNER can read both enabled and disabled PLAYER financial claims, the live roster omits a disabled player, logout revokes access from a saved cookie, and replaying the spent recovery code cannot issue a new cookie. None of the one-time secrets or cryptographic keys are committed to Git, printed, or returned by HTTP.

This test does **not** expose owner setup/enrollment through HTTP, authorize account creation or reassignment writes, approve reverse-proxy trust, verify a browser deployment, or prove backup/key-rotation operations. The owner still personally runs local first-owner setup; no self-service lost-all-factors recovery is added. The HTTP preview remains read-only and unable to authenticate. Immutable audit/accounting rows are left only in CI's disposable test database, which its job destroys.
