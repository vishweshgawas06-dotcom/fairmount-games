# P04-T02d — Reauthorized per-player wallet read

**Status:** Local checks and [CI 40188492976](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/40188492976) passed (Python 3.12/PostgreSQL, migrations, Node, Ruff). Disabled behind the HTTP proxy preview.

`GET /api/v1/players/{player_id}/wallet` is an opt-in **direct-TLS** projection, not authorization by URL. It accepts one canonical UUID and no query parameters. It checks transport/cookie shape, then validates the current PostgreSQL session and the proposed target inside one transaction. The data layer locks the target account; OWNER can inspect a PLAYER wallet including disabled-player financial claims, AGENT can read only a currently assigned enabled PLAYER, and PLAYER can read only their own enabled account. Non-PLAYER targets are refused for all roles. A moved assignment or disabled target is rejected on the next read; the session touch commits before response. Missing/unauthorized targets produce the same generic 404. Missing cookies produce 401; unavailable transport or database/schema produce 503. All responses are no-store with `Vary: Cookie` and `nosniff`.

HTTP boundary tests verify no DB call on edge/query/UUID failures, exact field projection, no assignment disclosure and generic DB failures. Transaction-scoped PostgreSQL tests verify role/assignment/disablement rules; the committed login→HTTP flow tests both self access and another player's refused ID using real database connections. This does not expose a player roster, history, mutations, real TLS deployment, or a full owner/agent HTTP login and reassignment acceptance flow. It is not enabled behind Arena's proxy preview.
