# P03-T01m — Restricted owner MFA key loading

**Status:** Implemented; Python 3.12 CI pending (2026-10-19).

**Authorization:** D-15 approves an owner-controlled deployment secret outside PostgreSQL/Git, offline backup and key versioning. This slice implements a **file-backed keyring loader only**, not enrollment, key generation, rotation, owner bootstrap or login. A deployment system may inject a secret as a restricted file and set `FAIRMOUNT_MFA_KEY_FILE` to its absolute path; no real key is supplied in the repo.

## Implementation

- Fail closed if the key-file path is missing, a symlink, non-regular, not owned by the running user, group/other-accessible, executable or larger than 4 KiB. Open with `O_NOFOLLOW`, `O_CLOEXEC` and `O_NONBLOCK`; check metadata on the opened descriptor. No fallback key.
- Accept strict JSON of the form `{"active_version": 1, "keys": {"1": "standard-base64-32-byte-key"}}`; allow at most eight distinct versions, validate exact 256-bit key length and active-version presence, and reject duplicate JSON names/ambiguous versions. The returned mapping is read-only. Do not print contents in errors. Older keys may remain available for decryption during a separately reviewed rotation; the loader does not re-encrypt or rotate.
- Unit tests create *ephemeral test-only random keys* and cover active/historical versions, missing configuration, unsafe modes, symlinks, directories, oversize, invalid shape and duplicates. No actual deployment key was created or committed.
