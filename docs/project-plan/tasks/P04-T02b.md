# P04-T02b — Direct-TLS self-only recent-bets projection

**Status:** Implemented; local HTTP/Ruff checks passed. PostgreSQL CI pending. Not enabled in the HTTP proxy preview and not gameplay.

`GET /api/v1/me/recent-bets` requires the existing opt-in direct-TLS boundary and a live enabled PLAYER session. There is no client account ID, query scope, or owner/agent access. The service derives the player ID from the validated session in the same transaction, locks that account, then projects at most 100 accepted bets newest first (acceptance timestamp and ID descending). The session touch commits before response. The response includes bet ID, round ID, selection key, accepted stake, and acceptance timestamp only; it does not claim a settlement outcome or provide pagination. Empty history returns `{"bets":[]}`. Responses use no-store, `Vary: Cookie`, and `nosniff`; session denials are generic 401, and missing DB/schema or transport configuration returns generic 503. All query parameters are rejected with 400 after edge authentication. No cross-player or cross-agent history route is exposed.

HTTP tests cover disabled mode, HTTP transport, missing/duplicate cookie, cross-site/forwarded assertions, client ID query rejection, exact projection, generic denial and DB/schema failures. PostgreSQL tests cover own bet, another player's empty history, OWNER/AGENT rejection and disabled-player rejection. They do not yet prove a committed end-to-end HTTP login→resource→logout flow, cross-account authorization at the edge, a browser deployment, production proxy trust, or wagering. The preview remains read-only.
