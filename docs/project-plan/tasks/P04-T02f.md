# P04-T02f — Direct-TLS live dashboard ID roster and owner audit gate

**Status:** Local checks and [CI 40189738375](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/40189738375) passed (Python 3.12/PostgreSQL, migrations, Node, Ruff). Not enabled in the proxy preview.

At P04-T02f, `GET /api/v1/me/players` accepted no query parameters or client-selected role/agent. P04-T02g subsequently added a single canonical `after` UUID cursor and a 100-ID page limit, without allowing any role/agent selector. It uses the existing direct-HTTPS, exact-host, no-forwarded-headers, same-site safe-GET boundary and one live session transaction. The existing transaction-scoped roster service returns **only IDs**: OWNER sees all enabled PLAYERs, AGENT only currently assigned enabled PLAYERs, and PLAYER only self. It locks/rechecks targets before the transaction commits, including reassignment and disablement. Revoked/disabled sessions receive generic 401; missing direct-TLS/schema/database configuration receives generic 503. Response headers are no-store, `Vary: Cookie`, and `nosniff`. A roster ID is **not** authorization for a subsequent wallet/bet request; each resource must recheck its own current scope.

HTTP adapter tests cover disabled mode/HTTP transport, missing or duplicate cookies, cross-site/forwarded assertions, query tampering, projected ID-only payload and generic errors. Committed PostgreSQL tests cover player self roster, agent cross-assignment, reassignment/disablement, and OWNER omission of a disabled player while the owner may still read that player's wallet as an existing financial claim. At this checkpoint the owner and agent sessions used for scoped read tests were seeded under DB constraints. P04-T02h subsequently added a real owner password + MFA HTTP login→resource→logout flow; agent login integration remains separate. Existing pure data-layer tests cover owner/player/agent scopes. Full UI, private field exposure, a bounded/paginated large roster contract, owner password/MFA login acceptance, reverse-proxy trust, and gameplay-write CSRF remain open. The preview stays non-playable and cannot authenticate.
