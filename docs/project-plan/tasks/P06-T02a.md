# P06-T02a / P07 console slice — scoped dashboards and administrative history

**Session date:** 2026-10-15. Earlier future-looking checkpoint dates are not

labels. **Status:** implemented and verified; supported CI passed on `f2ca384`. P06/P07 remain partial, not production-accepted.

## Scope, prerequisites and boundaries

Build on P06-T01b, P03-T03a, P07-T01a and P05-T04a, without changing their
accounting/authentication policies. Allowed scope: bounded read projections,
indexes, shared browser UI, tests and evidence docs. No new retention journal,
CSV/export, gameplay P/L, RNG/result/admission/settlement changes, proxy trust,
credential-reset policy, migration-history rewrite or launch permission.

The UI is an incremental framework-free shared adapter at `/console/`, not a
completed implementation of the originally proposed Next.js apps. No
third-party assets, demo identities or fake successful writes are included.

## Read contracts

All three GET routes require the existing direct-TLS edge, live HttpOnly session,
ready schema, `no-store` / `Vary: Cookie` / `nosniff` responses, generic denials,
and server-derived OWNER/AGENT scope. PLAYER sessions cannot use them. Unknown,
duplicate or malformed query parameters fail closed.

| Route | Projection / pagination |
|---|---|
| `/api/v1/console/context` | Actor UUID, role, exact decimal-string own balance, DB observation time and owner MFA-refresh flag. Reserve balance only for OWNER. No query parameters. |
| `/api/v1/console/members?after=<canonical UUID>` | At most 50 roster rows, UUID-keyset continuation. OWNER sees agents/players including disabled accounts; AGENT sees only currently assigned enabled players. Candidate rows are reauthorized under account/current-assignment locks before private identity projection. Returns identifier/display name, status/role, decimal-string balance, current agent UUID and pending-activation boolean; no contact number, hash or secret. |
| `/api/v1/console/history?after=<cursor>` | At most 50 administrative movements ordered by `(created_at, UUID)` descending. Strict bounded canonical base64url UTC-time/UUID cursor is an ordering position, never authority. OWNER administrative history; AGENT own `AGENT_TRANSFER` rows only, with current enabled-player reauthorization for each row. Sparse pages can be empty but still have a continuation. |

Administrative kinds: owner issuance/transfers, agent transfers, reserve
fund/withdraw and disable-return. No BET/PAYOUT/VOID_REFUND rows, credentials,
contact numbers, request keys, fingerprints or general ledger dump. Amounts use
strings to avoid browser BIGINT rounding. This is not net gameplay profit/loss.

Migration `20261107_03` adds partial administrative `(created_at,id)` and
`(actor_account_id,created_at,id)` indexes, with metadata/readiness parity.
Existing append-only data is unchanged; index downgrade is reversible even with
history. Older receipt/audit-preservation downgrade guards remain intact.

## Console behavior and failure acceptance

- Owner MFA/agent login, logout and role-derived navigation; confirmation before
  creation, assignment/unassignment, enable/disable, pending-secret reissue,
  issuance/transfers and reserve changes. No holder password is requested.
- Backend remains sole authority for balances, affordability, current scope,
  recent owner MFA and accepted payout/full-refund reserve coverage.
- Decimal-string balances display exactly. Write amount validation accepts only
  positive whole safe integers; it explicitly refuses larger values rather than
  silently rounding. Reasons remain required by the existing point API.
- Every intent has one UUID key and frozen serialized body, retained in memory
  across retries. Duplicate in-flight sends are blocked. Unknown 5xx/network/bad
  acknowledgments remain unresolved even if a later retry gets 4xx. Cancellation
  is blocked while uncertain; a before-unload warning explains the risk. A crash
  still requires journal reconciliation, not blind new-key resubmission.
- Pending commands retain the original actor UUID. Before dispatch, a fresh
  context read and a **prior** CSRF-cookie snapshot prevent cross-tab account
  replacement from silently rebinding the command to a different session.
- One-time secrets use masked fields; close/logout/background/auth failure clears
  them. Secrets/credentials never enter URL parameters, HTML interpolation,
  browser storage, logs or replay receipts. An acknowledged replay delivers no
  secret; the owner can reissue a still-pending one.
- Session loss/read failure clears private views. Generational guards reject late
  responses after logout/backgrounding, including late write-secret responses.
  Successful writes refresh confirmed state; no optimistic balance fiction.
- Native dialogs/keyboard focus, live errors/status, safe text rendering,
  desktop/phone/landscape layouts, table containment and reduced-motion CSS.
  Static `no-store`, self-only scripts/styles/connect, no-referrer/nosniff; actual
  direct-TLS mode additionally forbids third-party framing. Disabled preview
  shell remains embeddable without enabling its privileged APIs.
