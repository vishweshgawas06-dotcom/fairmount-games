# P03-T02c — Internal owner MFA proof, single-use factors and success audit

**Status:** Complete (2026-10-19); [CI 39205477305](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/39205477305) passed.

The owner approved mandatory TOTP and ten single-use offline recovery codes. This narrow slice adds an internal caller-transaction `verify_owner_mfa` for an already password-verified owner login or a separately authorized session step-up. The service locks Account → AccountCredential → OwnerMFA → recovery code, requires enabled/activated/confirmed owner, reads PostgreSQL `clock_timestamp()` after locks, decrypts the TOTP seed with the external versioned key, accepts only a newer time-step, or matches/consumes one stored recovery digest. It writes an append-only `OWNER_MFA_VERIFIED` event atomically, with no code, seed or factor type in the event. The returned timestamp is **not** a login or a grant of management access. Revision `20261019_02` extends the event type check; a downgrade after verification events requires a retention review rather than deleting audit rows.

The SELF_SERVICE actor field records the target owner account, **not a proven session**. Failure reporting and lockout/rate limiting must be added at the request boundary without rolling back failure records. Do not expose this function as an endpoint: its caller must first verify password or an existing authorized owner session, enforce throttling and commit the proof with the intended session action. No token issuance, cookie, login route, sensitive-action authorization or production recovery service exists. No all-factors-lost bypass is added. The [storage boundary](../auth/OWNER_MFA_STORAGE_BOUNDARY.md) and [session boundary](../auth/SESSION_SCHEMA_BOUNDARY.md) still apply.
