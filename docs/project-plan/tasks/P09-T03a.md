# P09-T03a — bounded private snapshot streams

**Session date:** 2026-10-15. **Status:** implemented and verified; supported CI green on `c051f66`.

## Brief / prerequisites

Build on P04 live authorization, P03 sessions/direct-TLS boundary and P09 public
SSE framing. Scope: self wallet/recent accepted bets and authorized single-player
wallet streams; no broadcast rooms, client role claims, contact fields, replay
log, assignment cache, retention policy, gameplay mutation or deployment bypass.

Acceptance: authorize on every DB poll under current account/session/assignment
locks; never extend idle deadlines from autonomous event polls; generic close
on denial/outage with no cached private replay. Decimal-string points, bounded
100-bet self projection, per-stream order and replace-on-reconnect semantics.
Process/per-session concurrency caps, finite lifetimes and disconnect cleanup;
no secrets in URLs/events/logs. Targeted-player streams expose only wallet data.

Test before completion: pure framing/order/changed-only/close/bounds/cancellation;
real PostgreSQL open-stream transfer updates, reassignment/disable/logout and
idle expiry, cross-player/role denial, self private-field exclusion and HTTP
transport/header/shape limits. Run fresh cumulative suites, schema parity,
frontend tests, lint/docs checks and supported CI. Keep ordinary preview private
APIs disabled; no production, end-to-end browser or load acceptance is inferred.


## Implemented protocol and limits

- `GET /api/v1/me/stream`: actor-derived wallet (all roles); PLAYER additionally
  gets at most 100 own accepted bets ordered by acceptance time/UUID. Accepted
  stake and wallet values are decimal strings. Accepted-bet history is not a
  settlement, winnings, pending-payout or gameplay P/L projection.
- `GET /api/v1/players/{uuid}/stream`: authorized player wallet only. OWNER can
  audit disabled player claims; AGENT requires an enabled currently assigned
  player; PLAYER can see only self. No cross-player bet feed, roster broadcast,
  role-selected room, contact information, credential or reserve disclosure.
- Existing opt-in direct TLS, live HttpOnly cookie and schema readiness before
  headers, then **again on every poll**. No query parameters (including token
  URLs); one bounded numeric Last-Event-ID may be ignored as reconnect metadata,
  never used as authority to replay private events.
- `retry: 3000`, changed-only `snapshot` events, per-connection IDs 1,2,…,
  15-second comment heartbeats, one-second authorization polls and nominal
  60-second lifetime. Reconnect replaces the full bounded projection; IDs restart
  and are not a durable/replay sequence. No accounting effects originate here.
- Denial/expiry/revocation/reassignment or DB/schema failure after headers emits
  only generic `unavailable` then terminates; **never** keep emitting old private
  payloads or silently recover into cached-scope replay. Before headers: generic
  401 scope/session, 400 invalid request shape, 503 backend/capacity/configuration.
- Thread-safe process cap 32 streams, maximum two per session digest, no waiting
  queue. Counters/digests exist only in process memory and are removed on close,
  cancellation or error. Limits are protective defaults, not approved D-04 load
  targets or distributed/admission-policy proof.
- DB reads run outside the event loop and finish short transactions before I/O.
  `SET LOCAL` 500ms lock/2s statement limits prevent a held account lock pinning a
  read indefinitely. Slow completed polls cannot emit after lifetime expiry.
  These bounds are not an Internet-delivery or failover SLO.
- `resolve_session(..., touch_idle=False)` retains all live role/status/expiry/
  revocation checks without extending `last_seen_at` or the idle deadline.
  Autonomous streams and console snapshots use it; normal authenticated actions
  preserve existing idle activity behavior. An unattended dashboard cannot defeat
  idle logout by continuing its automatic refresh.
- `no-store`, `Vary: Cookie`, `nosniff`, event-stream MIME and no-buffer hint.
  Default proxy preview remains denied; no forwarded-header trust is added.

## Still open

Browser EventSource integration must discard private state on `unavailable`,
logout, backgrounding and actor change; close/reconnect must replace snapshots,
not append old per-stream sequences. Operator/player UI does **not yet consume**
these streams; this is a backend contract checkpoint, not immediate UI revocation
or end-to-end deployed browser evidence. Per-source/distributed load protection,
approved targets, measured reconnect/failover behavior, workload/security testing,
full gameplay/status projections, deployment and release gates remain open.
