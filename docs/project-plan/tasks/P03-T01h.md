**Status:** Implemented; PostgreSQL CI verification pending.

**Authorization:** Owner granted staged implementation permission. Approved 24-hour initial credentials for agent/player (P03-T01a) and owner (D-12), Argon2id permanent passwords (D-10/D-13), and owner MFA before management (D-03/D-12). This slice is schema and tests only, not a route or CLI.

## Deliverable

[Activation-state boundary](../auth/ACTIVATION_STATE_DESIGN.md) and Alembic revision `20261016_06`: one `account_credentials` row per account. Pending state stores a lowercase SHA-256 digest of a 256-bit generated secret and issued/expiry timestamps exactly 24 hours apart; active state stores a password hash with consumed/changed timestamps and **no initial digest or expiry**. A DB trigger prevents active → pending regression or deleting an active row. Pending reissue can rotate digest/timestamps, but no reissue API or CLI exists yet.

PostgreSQL tests exercise valid pending/active state, invalid digest/shape/expiry, uniqueness/FK, pending rotation, and blocked regression/delete. Database constraints cannot verify possession or expiry against the current time, authorize a creator, enforce owner MFA, prove a complete Argon2id hash, or record an audit event. Those remain mandatory future service gates; `accounts.status = ENABLED` does not imply a usable credential.
