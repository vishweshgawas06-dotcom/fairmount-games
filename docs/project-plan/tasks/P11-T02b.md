# P11-T02b — Independently committed rebet contention

**Status:** Local checks and [CI 40083052003](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/40083052003) passed (Python 3.12/PostgreSQL, 2026-10-24). Test-only, not deployed.

A disposable migrated PostgreSQL schema runs two concurrent independently committed callers against the same authenticated player. Two attempts with one rebet idempotency key must create precisely one target bet and one unchanged replay. In a later round with barely sufficient reserve, attempts with distinct keys must yield precisely one admitted bet and one rejection under POOL-01. Both cases verify player/reserve balances, total persisted bets, and final ledger reconciliation. The Account → reserve lock discipline serializes these competing requests without client-visible partial acceptance. The fixture's privileged time warp restores the round guard before any service operation; it is not a production clock control.

This is a focused two-connection race, **not** a load/SLO test. Request-edge routes/CSRF, a regulated rebet UX and broader multi-player contention still remain.
