# P03-T02l — Restricted authentication HMAC key custody

**Status:** Local pure checks passed (2026-10-24); CI pending. No HTTP authentication route.

The P03-T02i pseudonymous failure-audit guard requires a 32-byte random deployment-owned HMAC key **distinct** from the owner TOTP encryption secret. `identity/auth_hmac_key.py` now reads only a restricted, owner-owned regular file named by `FAIRMOUNT_AUTH_HMAC_KEY_FILE` or an explicit trusted path. It requires mode 0600 or stricter, rejects symlinks/directories/overlong or malformed/noncanonical base64, allows at most one trailing newline, and has no default/test fallback. Errors never print the key or configured path. Unit tests cover file/env success and unsafe/absent inputs. Never put this key, a real example value, or a production path in Git or chat.

Before a public login deployment: define protected file provisioning/backup, who may rotate it, key-version/rotation behavior (changing it intentionally resets active throttle buckets and makes old pseudonyms unlinkable), reverse-proxy peer-IP trust, D-02 audit retention and incident runbook. Loading a key is not evidence that HTTP authentication is rate-limited or certified.
