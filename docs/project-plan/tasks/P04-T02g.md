# P04-T02g — Bounded, live-keyset player roster pages

**Status:** Implemented; local HTTP/Ruff and non-DB checks passed. PostgreSQL migration/transaction CI pending.

`GET /api/v1/me/players` now returns at most 100 visible PLAYER UUIDs and `next_after` (canonical UUID or null). The only optional query field is a **single canonical** `after` UUID; repeated/unknown/invalid parameters give generic 400 before DB access. Call the same endpoint with `?after=<next_after>` until it is null. Cursors are position markers, not authorization grants; each page revalidates the current session, role, enabled status, and agent assignment. There is no frozen cross-request snapshot: changes between pages may change which IDs appear, and a subsequent resource request still checks its own scope. No offset/count/role/agent selector is accepted. Responses stay no-store and direct-TLS only, never enabled through the HTTP proxy preview.

For OWNER, SQL locks and returns at most 101 enabled player rows ordered by UUID (one-row lookahead). For AGENT, SQL reads at most 101 currently assigned candidate IDs by UUID and transaction-scoped authorization rechecks at most 100 of them under account/assignment locks. A page cursor advances past the last candidate scanned even if a concurrent reassignment/disablement made that candidate ineligible; thus a stale row cannot cause an unbounded in-process scan or an endlessly repeated page. An empty page with non-null `next_after` is possible under concurrent changes; clients must continue. PLAYER receives only self once. A new partial composite index `(agent_account_id, player_account_id) WHERE ended_at IS NULL` supports the keyset query without loading the whole agent history. Migration `20261025_01` bumps the exact readiness revision; deployments must migrate before enabling database-dependent routes. Existing unpaginated *private* helper remains internal only and is not used by the HTTP roster.

HTTP tests cover strict cursor parsing and projection; transaction-scoped PostgreSQL tests cover over-100 owner/agent pages and disablement between pages; existing committed HTTP tests cover small owner/agent/player rosters and revocation. These tests do not establish high-load latency, a browser deployment, owner MFA login or general UI readiness. Full operational performance thresholds, load tests and production proxy trust remain open.
