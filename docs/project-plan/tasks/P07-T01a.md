# P07-T01a — agent-created assigned players and required registration profiles

Status: implemented and tested, **opt-in direct TLS only; P07 remains partial**.
Date: 7 November 2026.

## Scope

`POST /api/v1/agent/players` accepts exactly `username`, `display_name`,
`mobile_number` under the same direct-TLS origin/cookie/CSRF, bounded JSON,
idempotency and attempt guards as owner writes. Authenticate an enabled live
**AGENT** session before lookup or replay. Derive the agent solely from that
session; reject supplied agent/owner IDs, role, balances or assignment flags.
Owners/players cannot invoke the agent-only path. Agents cannot create sub-agents,
reassign preexisting players, issue points or reset/reissue credentials here.

In one transaction: canonical globally unique username → new PLAYER/private
profile → zero-balance wallet (existing DB trigger) → digest-only 24-hour
credential → assignment to the authenticated agent → two audited events
(`INITIAL_CREDENTIAL_ISSUED`, `AGENT_ASSIGNED`) with the actual agent actor →
non-secret replay receipt → commit → first-response secret delivery.

A revoked/disabled/stale session cannot create or replay. A duplicate username
is a generic denial, not a partial registration or database outage. A savepoint
contains the named private-identity unique-index conflict, preserving the outer
attempt counter; unexpected SQL faults still fail as 503 and roll back.

## Owner registration/profile compatibility

The owner `/operator/agents` and `/operator/players` HTTP routes now also require
`display_name` and `mobile_number`; prior lab bodies without these fields are
rejected (400), not silently assigned fake details. Internal legacy/fixture
helpers retain optional profile parameters; existing rows are **not** backfilled
with invented names or numbers.

Names: 1–160 printable Unicode characters, nonblank. Contact numbers: 1–32
printable characters, nonblank. Input is retained verbatim in `private_identities`;
no new country-specific normalization or verification policy is invented.
Numbers may be shared, are explicitly **unverified contact text**, and never
select an account or authorize credential reset. This bounds storage; it does
not claim a number exists or is reachable. Profile data is absent from public
rounds, wallet/creation responses and replay payloads; request fingerprints are
one-way digests, not copied registration bodies.

## Replay migration

`20261107_02` renames receipt `owner_account_id` to `actor_account_id` without
recreating/deleting rows. Existing owner receipts remain readable. Agent
receipts use the authenticated agent as their key, so two actors using the same
UUID cannot read or collide with one another's receipts. Same actor/key/body
replays the account reference without its secret; a changed body conflicts.
Replay never restores a previous assignment or rewrites account state.

Downgrade refuses if agent-owned receipts exist rather than presenting them to
old owner-only code. Receipt immutability and no-secret checks remain in force.
