# P09-T01a — Private public-safe round snapshot projection

**Status:** Local checks passed; PostgreSQL CI pending. No HTTP/realtime event contract or UI.

`roulette/public_snapshot.py` reads database-clock and persisted round rows only: current round ID, phase, cutoff/reveal timestamps, result if and only if revelation is due, and up to 20 previously revealed result/exceptional-void rows. It never selects or returns bets, player identities, stakes, balances or the RNG source. A persisted CLOSED result is **withheld before** its reveal deadline; after reveal it may be displayed even if settlement has not yet committed. OPEN past reveal is represented as `RESULT_DELAYED`, never a fabricated loss, result or timeout void. The result remains the server's immutable persisted number, not animation output.

PostgreSQL tests check result withholding with a persisted winning number, release at reveal, latest/current rollover, absence of private data in the projection and an overdue missing-result case. Fixture-only time warps restore the DB round guard before service calls. This is a **private** projection, not a public API/realtime event; D-08 event versioning/replay, authentication for player-private updates, worker supervision, read load and client reconnect still need separate gates.
