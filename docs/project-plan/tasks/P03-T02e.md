# P03-T02e — Internal owner MFA recency and session-bound step-up

**Status:** Implemented; PostgreSQL CI pending (2026-10-19).

D-03 requires sensitive owner actions to use MFA within ten minutes. `require_recent_owner_mfa` resolves and locks an enabled, unexpired owner session using the existing digest/DB-time validator, then checks its recorded MFA verification timestamp against fresh PostgreSQL time. It returns session data only when the timestamp is between now minus ten minutes and now. That result is **not** resource/action authorization; a future sensitive action must use it and enforce its own policy in the same transaction, before releasing account/session locks.

`step_up_owner_session` requires possession of an existing live owner bearer token, verifies another TOTP step or one offline recovery code under owner locks, atomically updates that **same** session's MFA timestamp/idle deadline within its fixed absolute deadline, and uses P03-T02c's success audit. It never issues another token or extends the eight-hour absolute timeout. On transaction rollback the factor consumption, timestamp, idle touch and success event are undone. Failure throttling/auditing is still a request-boundary prerequisite; this function must not be exposed publicly yet. No owner action route or authorization grant exists.
