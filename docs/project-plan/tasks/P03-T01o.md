# P03-T01o — Internal initial owner activation transaction

**Status:** Implemented; PostgreSQL CI pending (2026-10-19).

**Authorization:** D-12 approved the owner-run local one-time setup, 24-hour expiry and MFA before management. D-13 approved permanent-password policy. This slice adds only an internal transaction function; no route, CLI, owner session or access grant.

## Implementation

- `activate_initial_owner(connection, secret, new_password)` locks OWNER then credential (same order as reissue), requires enabled/pending state and no MFA factor, compares the supplied high-entropy secret digest, checks expiry against PostgreSQL `clock_timestamp()` before and **after** Argon2id password hashing, then clears the digest/expiry and atomically stores password/consumption timestamps plus an `INITIAL_CREDENTIAL_CONSUMED` security event. Bad/missing/expired/replayed secrets fail with the same non-enumerating error; weak permanent passwords fail policy validation. A caller must commit; rollback removes the password and event together.
- PostgreSQL tests cover success and replay rejection, wrong/rotated secret, weak password, expiry, disabled owner, and rollback without partial state. The audit event attributes the provisional account, not a fully authenticated MFA session.
