# P05-T02d — Real two-connection owner transfer contention

**Status:** Test harness and real PostgreSQL contention passed (2026-10-23); [CI 39912341630](https://github.com/vishweshgawas06-dotcom/fairmount-games/actions/runs/39912341630). No public route.

`tests/test_point_concurrency.py` creates a disposable PostgreSQL schema with the **same Alembic revisions**, not SQLite or a mock. It commits an owner, session, zero player wallets and one explicit 100-point issuance there. Two worker connections start together and attempt different 70-point owner transfers: the owner Account lock must serialize them; only one can succeed and the loser must reject the **entire** request. Then two connections retry the *same* five-point transfer with one key and identical intent: exactly one journal operation must exist, both obtain that operation ID and one reports replay. Finally the test checks all account balances, journal operation count, stable-snapshot reconciliation and unchanged 100-point total supply. The temporary schema is dropped after the run, leaving existing identity tests unmodified.

This exercises a real PostgreSQL race, but **not** every possible interleaving, assignment/reassignment/disable contention, reserve-versus-bet admission, or load/SLO performance. If CI cannot migrate the disposable schema cleanly, fix the test or implementation rather than claiming coverage.
