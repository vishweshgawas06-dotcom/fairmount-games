# P03-T01l — Encrypted owner-factor and hashed recovery-code schema

**Status:** Implemented; PostgreSQL CI verification pending.

**Authorization:** Owner approved D-03 TOTP/one-time offline recovery, the count of **ten** codes, D-15 external key custody and broad step-by-step implementation. This slice is database storage/tests only; [boundary](../auth/OWNER_MFA_STORAGE_BOUNDARY.md) explains why it is not an MFA service.

## Implementation

- Alembic revision `20261016_08` creates `owner_mfa` with OWNER-only composite FK, key version, AES-GCM nonce/ciphertext, confirmation time and last accepted step. Checks reject invalid structural shapes and a used step before confirmation; they cannot decrypt or authenticate a factor.
- `owner_recovery_codes` stores digest/issue/consumed times with owner FK and per-owner digest uniqueness. A trigger allows one consume transition then blocks edits, deletes and truncation. PostgreSQL tests cover role/FK/ciphertext shape, duplicates, consumption/replay mutation, attempted deletion and migration round-trip.
- There is no key in the DB/repository and no live enrollment, code matching, rate limiting, audit-writing or session authorization service. The DB does not enforce exactly ten codes at confirmation; that is a future atomic enrollment-service invariant.
